# Multi-harness memory server: same repo, Python stays, adapters + migration + memory diet

## Context

The daemon (v0.11.10, healthy) works well with Claude but hits 3 GB+ RSS under many-agent / sync workloads, and everything outside the core is wired to Claude specifically. Decisions locked with the user: **stay in Python and fix memory; restructure this same repo** around a harness-adapter contract; add **ZCode, Codex, OpenCode** adapters (each verified live before shipping); auto-migrate `.claude-memory` → **`.agent-memory`**; rename the git merge driver to **`agent-memory-snapshot`** (our own app registers it machine-wide, so setup fixes it globally on install and update).

Execution model: milestones below become tasks on the bound asoode board (memory_task_plan, full descriptions), worked one at a time; each milestone bumps and ships per the release rules.

---

## M1 — Memory diet (measure → fix → re-measure)

1. **Instrument.** Add `psutil` dep; `/api/health` gains `rss_mb` and `open_db_handles`; a log line every 60s from the daemon lifespan (rss, handle count, model backend). Measure a baseline reproduction (several concurrent agent sessions + a board sync) and record numbers before changing anything.
2. **ONNX embedding backend.** `config.py`: `embedding_backend: str = "onnx"` (env `MEMORY_MCP_EMBEDDING_BACKEND`, `torch` fallback). `embeddings.py:23` passes `backend=settings.embedding_backend` to `SentenceTransformer`. Deps: add `optimum[onnxruntime]`; drop torch from the runtime path (sentence-transformers keeps it optional). Same MiniLM weights → same 384-dim vectors, **no re-embedding**. Test: embeddings from both backends on a sample corpus, pairwise cosine ≥ 0.999; search ranking unchanged.
3. **DuckDB idle-handle LRU.** `db/connection.py` (all primitives exist: `_quiesce_and_close`, tracked cursors, `_databases_lock`): new `close_idle_databases(max_handles, idle_seconds)` using monotonic last-use per key; piggyback the call on the existing 60s outbox-sweeper loop (`container.py`). Settings: `db_max_open_handles` (default 8), `db_idle_close_seconds` (default 900). Never closes a handle with live cursors/ambient transactions — `_quiesce_and_close` already refuses that.
4. Re-measure the same workload. Report before/after RSS to the user. Target: steady-state well under 1 GB.

## M2 — Harness adapter contract (behavior-preserving extraction)

1. New package `src/memory_mcp/harnesses/`:
   - `base.py` — `Harness` protocol: `name`, `detect() -> bool`, `capabilities` (dataclass: `hooks`, `agents`, `per_turn_line`, `edit_gate`), `configure_mcp(server_url) -> ChangeReport`, `install_hooks() -> ChangeReport`, `install_agents() -> ChangeReport | NotSupported`. `ChangeReport` = files written + **conflicts detected** (existing MCP entry named `memory` pointing elsewhere → report and ask, never overwrite — the SMG-fork lesson).
   - `claude.py` — move today's logic out of `setup.py` verbatim: `setup_claude_mcp`, `setup_hooks` (HOOK_EVENTS/HOOK_MATCHERS), `setup_agents`/`compose_agent`/`retire_default_agent`. Golden test: adapter output byte-identical to current installer output.
2. `setup.py` becomes the orchestrator: `--harness auto|claude|zcode|codex|opencode|all` (default auto = every installed harness), ordered adapter runs, per-harness report printed. **Fix `run_update()` to run adapters too** (today it skips `setup_hooks`, so hook edits only landed on full setup — known gap in memory).
3. Contract test: every adapter implements the protocol; `claude` adapter registered as default.

## M3 — `.agent-memory` migration + merge-driver rename

1. `constants.py`: `SNAPSHOT_DIRNAME = ".agent-memory"`, `LEGACY_SNAPSHOT_DIRNAME = ".claude-memory"`, `MERGE_DRIVER_NAME = "agent-memory-snapshot"`, `LEGACY_MERGE_DRIVER_NAME = "claude-memory-snapshot"`.
2. **Read order**: `context._uid_from_manifest` / `detect_project_from_cwd` read `.agent-memory` first, legacy `.claude-memory` read-only fallback (teammates on older clones).
3. **One-time rename** in `ProjectService.claim_folder` (and a pre-export check in `sync_cli`): legacy exists + new doesn't → `os.rename`; the inner `.gitattributes`/`.gitignore` travel with the folder; manifest content untouched (identity is `project_id`). Log to sync.log; idempotent; safe under concurrency via rename atomicity.
4. **Merge driver global fix** in `setup_merge_driver()` (runs on every install and update): write `merge.agent-memory-snapshot.*`; **remove the legacy `merge.claude-memory-snapshot.*` keys** from `~/.gitconfig` (same retire pattern as `retire_default_agent`). Per-project sidecars: every export already rewrites `.gitattributes`; migration also rewrites the driver line in place.
5. Tests: migration (rename, idempotency, legacy fallback, both-present precedence), gitattributes content, driver registration + retirement.

## M4 — ZCode adapter

- MCP: merge `mcp.servers.memory = {http server for 127.0.0.1:8765/mcp}` into `~/.zcode/cli/config.json` (preserve unrelated keys; conflict → report). Verify exact server-object schema against the installed client at implementation (source of truth: zcode-configuration-guide: user scope `mcp.servers`, fallback `~/.agents/mcp.json`).
- Hooks: register the same hook scripts (already installed to `~/.claude-memory-mcp/hooks/`) under ZCode's `hooks` key with `enabled: true`; ZCode has exactly the seven matching events (SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse, PostToolUseFailure, Stop). Verify ZCode's hook payload fields against what `inject-rules.sh`/`session-*.sh` parse (`cwd`, `session_id`, `tool_input`); add a thin per-event wrapper script only if the shape differs. Scripts fail open, so a mismatch degrades, never blocks.
- Agents: write composed definitions to `~/.zcode/agents/*.md`, frontmatter per ZCode's schema (verify fields at implementation; drop Claude-only keys).
- **Live verification**: open a ZCode session in a registered project — tools listed, rules injected, board brief, one task mirrored.

## M5 — OpenCode adapter (installed on this machine)

- MCP: global `~/.config/opencode/opencode.jsonc` — merge `"mcp": {"memory": {"type": "remote", "url": "http://127.0.0.1:8765/mcp", "enabled": true}}`. JSONC trap: the user's file may carry comments — implement a comment-preserving merge (no naive `json.load` overwrite).
- Hooks: OpenCode has no shell-hook surface; ship a small **plugin** (`~/.config/opencode/plugin/memory-mcp.js`, global plugins dir) that calls the existing daemon endpoints on its lifecycle events (prompt submit → `/api/hook/rules` + `/api/hook/attachments`; session idle → export + update-apply). Verify exact event names against the current docs at implementation.
- Agents: `agent/*.md` global dir if supported (verify); otherwise NotSupported — briefs ride MCP instructions + `memory_session_start`.
- Live verification with the installed binary.

## M6 — Codex adapter (needs install first)

- Install Codex CLI on this machine (required by the "no integration ships unverified" rule).
- MCP: `[mcp_servers.memory]` with `url = "http://127.0.0.1:8765/mcp"` in `~/.codex/config.toml` — Codex supports streamable-HTTP servers natively (`url`, `bearer_token_env_var`; no token in local mode). Prefer `codex mcp add` CLI when present, fallback to a TOML-aware merge.
- Lifecycle: `notify` hook wrapper → session-end export + update-apply; global `~/.codex/AGENTS.md` gains only a minimal wiring pointer ("a project with `.agent-memory/` is a memory project — call memory_session_start first"). Never project knowledge in instruction files (mirrors the CLAUDE.md forbidden rule).
- Capabilities: no subagents/roster → `install_agents` reports NotSupported; degradation is by design (tools + server instructions carry the core).
- Live verification.
